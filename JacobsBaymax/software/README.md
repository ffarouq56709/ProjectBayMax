# Software implementation plan

R0.1 | 2026-10-23 | Faisal Farouq

REWORK. R0.1 supplies schema/workflow specifications and fictional fixtures, not a working application. Build the laptop UI first with persistent SIMULATED banner and five interaction presets. Use local role accounts and a transactional local store. Separate companion gateway, consent, record, medication, deterministic summary, outbox and audit modules. The model receives no direct DB/motor/network privileges. Add typed APIs for propose_note, confirm_revision, record_simulated_observation, log_medication_response, preview_report, approve_report and send_approved_report. Every mutation validates actor, role, revision and confirmation. The outbox requires recipient allowlist and content-hash-bound approval; the default fixture has no approved recipient and cannot send.

Minimum observation fields: record_id, profile_id, simulated=true, metric, typed value, unit, source_id, actor_id, observed_at, recorded_at, statement_type, version, supersedes_id and correction_reason. Unknown values are null with a reason, never zero. Medication stores immutable original_instruction per authorized version; a response is a statement, not verified ingestion. Audit records create/read/change/transmit/deny with actor, target/version, time and result. Original audit events are append-only at application level; tamper evidence needs protected hashes/export and is not absolute immutability.

Priority enums: ROUTINE, CAREGIVER_ATTENTION, HUMAN_CONTACT_REQUESTED, SYSTEM_ASSISTANCE. Transmission states: DRAFT, APPROVED, QUEUED, ATTEMPTED, ENDPOINT_RECEIVED, DELIVERY_UNCONFIRMED, HUMAN_REVIEWED. HUMAN_REVIEWED requires a separate authenticated test-recipient action. No state represents emergency dispatch. Use a local receiver with idempotency keys and crash-safe retries. Bind all runtime inputs to documented fixtures; no EHR credentials. Next output is software/app with tests for JB-V-10 to 19 and 21, not physical control code.
